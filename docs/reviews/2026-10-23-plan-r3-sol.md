New comments

1. [major] C1/C4, run identity on event pulls - The new `sim_events_since(seq) -> { events, truncated }` contract identifies neither the requested run nor the returned run. A gap detected in a snapshot from run A can trigger an asynchronous pull that executes after LoadScenario or load_commit installs run B. The host then queries B's ring with A's cursor; the response cannot be distinguished from A's events and can be deduplicated or logged under the wrong run. Snapshot runId filtering alone cannot authenticate this separate response - Pass the expected runId with the pull and check it under the same sim lock as the ring read; reject a mismatch and include runId in successful responses. Before applying a response, the UI must also verify that its run is still current. Test a delayed pull across both scenario and saved-run transitions.
