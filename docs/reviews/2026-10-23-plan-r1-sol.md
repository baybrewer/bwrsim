1. [major] C2/C3/C5, save checkpoint — `useSim().send()` returns void and Tauri publishes snapshots only every 100 ms. Sending pause and immediately copying the current UI record can therefore save an engine state later than the final history sample and omit alarms/actions at the checkpoint. Locking engine state and summary together does not synchronize the UI payload — Define an awaited checkpoint operation that pauses and returns an authoritative snapshot plus run/revision identity; ingest that snapshot before copying the RunRecord, drain earlier commands, and prevent intervening mutations until capture completes. Test Save immediately after a command at high speed and verify the engine, history, and log represent the same checkpoint. Restore the prior pause state on cancellation or failure, and suppress that restoration after a successful load.

2. [major] A3/C2/C4, load and scenario transitions — `save_load()` returns only the UI payload, while old worker snapshots may already be queued for emission/delivery. Installing restored history can then be followed by an old snapshot that appends future data or triggers the backwards-time reset and erases restored history. Time comparison also cannot detect loading a scenario again while already at time zero — Add a run generation to snapshots and transition responses, reject snapshots from earlier generations, and install the loaded snapshot and RunRecord together. Reset scenario history/log explicitly at the successful transition rather than relying on decreasing time; seed alarm/scram comparison baselines from the restored snapshot. Test delayed pre-load events and repeated scenario loads at time zero.

3. [major] C2, worker backlog reset — Worker `backlog`, `last`, `last_emit`, `last_emit_time_s`, and `effective_speed` are local to the thread in `src-tauri/src/lib.rs`; replacing the mutex-protected Sim cannot reset them. A load that leaves the sim paused only clears backlog if the worker observes that pause before a resume, and a slow load can charge its lock wait to the restored run — Specify a worker reset generation or worker-owned transition request, consumed under synchronization before any advance. Reset wall-time anchors, host backlog, and speed-filter baselines on load, while preserving the saved engine `accumulator` required by exact restore. Test immediate resume after load and a load delayed by lock/I/O contention.

4. [blocker] C1-C4, validation before replacing a run — Version equality and serde deserialization do not establish a usable save. For example, independently sized rod `pos`, `target`, `weights`, and `fast_insert` vectors deserialize successfully but violate indexing invariants; the opaque `ui: Value` can have an unsupported RunRecord version or inconsistent history columns. Replacing the engine before the UI discovers such an error destroys the current run — Define structural/invariant validation for the engine and runtime validation for RunRecord, file format, and versions. Stage both payloads and validate them before committing either replacement, with a prepare/commit boundary if UI validation happens in TypeScript. A failed load must leave the active engine and record intact; test malformed vectors, history lengths, and unsupported UI/file versions.

5. [major] C2, save identifier trust boundary — Load/delete/overwrite accept an arbitrary string ID, but the plan gives no containment rule. Treating that string as a filename permits traversal outside `saves/`, and treating an unknown overwrite ID as a create bypasses the new-save limit — Require IDs to match the generated opaque basename grammar, resolve only regular files directly inside the save directory, reject symlinks/traversal, and reject overwrite of a nonexistent ID. Apply the same validation to load, overwrite, and delete and test hostile IDs and missing overwrite targets.

6. [major] C2, concurrent save mutations — Atomic rename protects one file from partial contents, but does not protect the count/name checks. Two concurrent creates with nine existing files can each pass and leave eleven; concurrent writes can also claim the same case-insensitive name or race deletion — Serialize list-check-mutate transactions with a save-store lock, including overwrite and delete; use unique temporary filenames and exclude them from slot enumeration. Test concurrent creates at nine slots and simultaneous same-name writes, asserting that exactly one succeeds.

7. [major] Architecture decision/C4/Q1, alarm capture guarantee — The decision relies on alarms being latched until acknowledgement, but `Sim::active_alarms()` computes current conditions and `acked` only affects presentation. A condition can clear without acknowledgement; transient `events` expire after 30 simulated seconds. The current history hook also mutates data during React render, which is not a reliable event ingestion boundary — Q1: retain UI-owned trend storage if the documented sampling loss is acceptable, but ingest snapshots once at the backend subscription boundary. Define whether the log promises every engine onset or every published/UI-visible alarm. If every engine onset is required, add sequenced engine transition events retained until consumed, with equivalent mock delivery; otherwise explicitly limit the guarantee to observed snapshots and remove the latch premise. Test a condition that appears and clears between publishes and multiple publishes before a React render.

8. [major] C4, alarm identity-only diff — Existing events reuse IDs with different visible messages, such as `scram_reset` changing from the ten-second wait to the SHUTDOWN block, or `turbine` changing its reset-block reason. `events` can also share IDs with condition alarms, including `msiv` and `rod_block`. An ID-only diff drops newly displayed warning text and a map keyed by ID can collapse distinct visible alarms — Give condition alarms and operator events distinct stable identities, and record material text/severity changes for an existing identity. Specify which continuously varying numeric text is coalesced. Test changed reset-block reasons and simultaneous condition/event entries with the same legacy ID.

9. [major] C4/C5/Q2, history query complexity — Tier 2 is explicitly unbounded, so reducing output to one envelope per pixel does not bound the work needed to find that envelope. Scanning all minute buckets for ALL still grows with run duration, contrary to the stated pixel-width drawing-cost guarantee; scanning the entire history for a one-minute view also defeats tiering — Q2: the proposed 1 h/24 h boundaries are reasonable retention defaults, but specify indexed time-range selection and cached multiresolution min/max summaries for long-range queries. Alternatively change the guarantee to acknowledge linear aggregation cost and provide measured limits. Test range-selection/aggregation work against increasing history lengths, including ALL, rather than checking only the number of drawn points.

10. [major] C4, nullable period channel — The registry requires every getter and history value to be a number, but `Snapshot.neutronics.periodS` is intentionally null when the period is effectively infinite. Substituting zero produces a false physical reading; using infinity or NaN is lossy through JSON and corrupts extrema/scale calculations — Allow an explicit missing value in the registry and history schema, define buckets to ignore missing values while retaining gaps, and apply the same rule to crosshair values and CSV. Test all-missing and mixed period buckets through JSON round trips and rendering queries.

11. [major] C1/test plan, exact-restore proof — Comparing only serialized snapshots after M steps cannot verify preservation of hidden integrator/clock state, and a restore forced paused must be explicitly resumed before testing `advance()`. The existing test helper advances through `step(DT)`, bypassing `accumulator`; JSON numeric equality also does not prove floating-point bit equality — Test a real serialized text round trip of complete engine state, compare float bit patterns and collections semantically with only the documented pause override, then resume and feed identical `advance()` durations with a nonzero fractional accumulator. Cover pending rod motion, controller integrals, acknowledgements/events, fault state, and later continuation. Do not compare unordered HashSet serialization order as a determinism requirement.

12. [minor] C2, origin-scenario metadata — Neither Sim nor Snapshot retains the originating scenario, and TopBar's local selected value is only the next scenario selection. It even starts at hotStandby while the desktop engine starts at coldShutdown. Deriving the save's `scenario` from that selector or current mode will write incorrect metadata — Store origin scenario in the authoritative run state, initialize it from the actual backend startup scenario, update it on successful scenario load, and restore it from saves. Make the mock export/import include the same metadata and test saving after changing the selector without loading it.

13. [major] C3, mock restore contract — `MockSim` has state outside Snapshot: `Hidden` includes controller integrals, precursor/decay state and an `alarmState` Map, and the class also keeps the synchronizing `phase`. JSON serializing the instance/hidden object loses the Map; restoring only Snapshot diverges on the next tick — Specify a versioned mock state payload containing Snapshot, all Hidden fields with explicit Map encoding, and phase. Restore these into the existing simulator without serializing listeners/timer handles, reset wall-clock measurement state, leave paused, and emit the restored snapshot. Add JSON round-trip continuation and acknowledged-alarm tests for the mock, not only the Rust engine.

14. [minor] A4/tasks/test plan/Q3, executable TS verification — The tasks' mandatory green checks are cargo test, tsc, and build; none executes the newly proposed Node tests. Native Node ESM also will not resolve runtime extensionless imports the way Vite does. `allowImportingTsExtensions` is already enabled in `ui/tsconfig.json`, so adding it does not fix those imports — Q3: Node 22 stripping is adequate for erasable, pure TS modules; use explicit `.ts` runtime imports throughout their dependency graph and keep React out of the logic modules. Add an exact test script and include it in task/CI completion checks. Prefer `.mjs` tests importing the TS logic if retaining the no-new-dependencies rule avoids needing Node type declarations. The local Node v22.22.1 successfully imports the existing pure `format.ts` with stripping enabled; also run the actual test graph once implemented.

15. [minor] Requirements/C4, destructive action coalescing — Replacing successive setpoint actions with a single start/end entry discards intermediate operator inputs. A pressure sweep up and back down within two seconds can appear to have made no change, despite the requirement to log every action and the possibility of plant response during that interval — Preserve individual actions in the underlying record and coalesce their presentation, or store the full timestamped command sequence inside a grouped entry. Include count/start/end timing in the displayed group and preserve the underlying actions in export; test a setpoint that changes and returns to its original value within the coalescing window.
